🚀 Crew Platform — Supabase Setup

Go live in ~20 minutes. You need a Supabase account and Vercel project.

1 Create your Supabase project

Go to supabase.com → New project → choose ap-southeast-2 (Sydney) for Australian data residency.

Project name: crew-platform  ·  Database password: save this somewhere safe — you won't need it often but can't recover it.

2 Run the schema SQL

In your Supabase Dashboard → SQL Editor → New query. Paste the entire contents of supabase_schema.sql and click Run.

This creates all 13 tables, row-level security policies, auto-ref triggers, and demo seed data.

Important: Run the full file in one go. The tables depend on each other — partial runs will fail.

3 Create Storage buckets

Dashboard → Storage → New bucket. Create these two:

Bucket name: form-photos    Public: ✓
Bucket name: job-photos     Public: ✓

Then add a storage policy to each: Dashboard → Storage → Policies → New policy → "Allow authenticated users to upload".

Dashboard → Settings → API. Copy your Project URL and anon public key.

5 Add supabase_client.js to your project folder

Copy supabase_client.js into your project folder alongside the HTML files. The Supabase JS library loads from CDN — no npm needed.

The auth.html file now loads Supabase directly. For the large app files (Command Centre, CrewBase Dashboard), add this line inside <head>:

<script src="supabase_client.js"></script>

6 Create the demo user account

Dashboard → Authentication → Users → Invite user. Create:

Then run this SQL to link the demo user to the seed organisation:

-- Run in SQL Editor after creating the demo auth user
insert into users (id, email, name, role, org_id, avatar_initials)
select 
  id,
  'demo@crewplatform.demo',
  'Demo Admin',
  'admin',
  'a1b2c3d4-0000-0000-0000-000000000001',
  'DA'
from auth.users 
where email = 'demo@crewplatform.demo'
on conflict (id) do nothing;

7 Deploy to Vercel

From your project folder:

vercel --prod

That's it. Vercel serves all the HTML/JS files as static assets. Supabase handles all the data, auth, and realtime.

After first deploy: Go to your live URL, click "Sign In", use demo@crewplatform.demo / CrewDemo2026! and you'll land on the Command Centre with live data.

8 Enable Realtime for the activity feed

Dashboard → Database → Replication. Enable replication for these tables:

  • jobs
  • time_entries
  • messages
  • workers

This makes the Live Activity Feed in the Command Centre update in real time when workers clock in, complete jobs, or send messages.

9 Wire the CC Activity Feed to live data

The Command Centre's live activity feed currently uses hardcoded data. To connect it to Supabase, add this snippet at the end of Command_Center_Desktop.html before </body>:

<script src="supabase_client.js"></script>
<script>
crewReady().then(async function() {
  // Load initial stats
  try {
    var stats = await CrewData.getJobStats();
    var el = document.querySelector('.live-monitor-count');
    if (el) el.textContent = stats.activeWorkers + '/' + (stats.totalJobs || 8) + ' active';
  } catch(e) {}

  // Subscribe to live job updates
  CrewRealtime.onJobChange(function(payload) {
    var job = payload.new;
    var feed = document.getElementById('liveActivityFeed');
    if (!feed || !job) return;
    var item = document.createElement('div');
    item.className = 'activity-item new';
    item.innerHTML = '<div class="activity-icon">📋</div><div class="activity-content"><strong>' + (job.service_type||'Job') + '</strong> — ' + (job.suburb||job.address||'') + ' <span class="activity-badge">' + job.status + '</span></div>';
    feed.prepend(item);
  });
});
</script>
